Question Storming

Uniquement des questions. Zéro réponse. Quinze sondes lancées dans le noir.
mode profond
~/db_query · question-storm 15 requêtes · 0 réponse
  • ?Pourquoi le monde aurait-il besoin d'un 12e query builder PHP alors que Doctrine, Eloquent, Cycle, Atlas et Medoo existent déjà ?
  • ?Quel problème de base de données en PHP fait encore perdre des journées entières à des gens en 2026 ?
  • ?Combien de lignes de PHP legacy concatènent encore du SQL à la main aujourd'hui dans le monde ?
  • ?Qui se réveille la nuit à cause de sa couche d'accès base ? Le dev, l'ops, le RSSI, ou le DPO ?
  • ?Pourquoi un dev choisirait-il d'ajouter une dépendance plutôt que d'écrire trois lignes de PDO ?
  • ?Qu'est-ce qui rend un outil open source PHP massivement installé : résoudre un besoin, ou s'insérer dans un pipeline existant ?
  • ?Est-ce que le problème est d'écrire du SQL, ou de vérifier du SQL que quelqu'un d'autre a écrit ?
  • ?Si un LLM écrit désormais la moitié du code d'accès base, qui vérifie ce qu'il a écrit ?
  • ?Pourquoi les outils de sécurité SQL existants (PHPStan, Psalm) ne détectent-ils presque aucune injection réelle ?
  • ?Qu'est-ce qui empêche une équipe de migrer 200 000 lignes de SQL concaténé vers des requêtes préparées ?
  • ?Pourquoi personne ne peut répondre à « quelles requêtes de mon app touchent des données personnelles ? »
  • ?Combien de DELETE sans WHERE partent en production chaque jour dans le monde ?
  • ?Pourquoi un audit de sécurité base de données coûte-t-il un consultant et pas un composer require ?
  • ?Quelle est la question qu'un dev PHP tape dans Google à 2 h du matin et pour laquelle il n'existe aucun outil ?
  • ?Est-ce que la valeur est dans le code qu'on écrit, ou dans la preuve qu'on peut donner que ce code est sûr ?

Aucune de ces questions ne porte sur la syntaxe d'une API fluide. Toutes portent sur la confiance, la preuve et la dette existante. C'est le premier signal.

02

Les Cinq Pourquoi

Descente en profondeur sous « un query builder de plus ». Chaque palier creuse d'un niveau.
mode profond
Pourquoi 1

db_query n'a pas d'utilisateurs. Parce qu'il n'apporte rien qu'Eloquent n'apporte déjà.

Pourquoi 2

Parce qu'il résout « écrire du SQL », un problème déjà résolu onze fois et devenu une commodité.

Pourquoi 3

Parce que le problème choisi était celui de l'auteur (apprendre), pas celui du marché.

Pourquoi 4

Parce que le vrai problème douloureux n'est pas l'écriture, mais la confiance dans le SQL existant.

Pourquoi 5 · racine

Il n'existe aucun outil PHP qui réponde « mon accès base est-il sûr ? » de façon automatisée et prouvable.

RACINE

Insight racine

Le marché du builder est saturé ; le marché de la vérification d'accès base en PHP est vide.

Insight brutal

L'histoire de db_query est elle-même la preuve du problème : escape_data() a livré un no-op d'échappement qui n'a jamais échappé personne.

Marché A · écrire du SQL
Saturé — 11 occupants
Doctrine · Eloquent · Cycle · Atlas · Medoo · Aura · Propel · Zend_Db · Laminas · Nette · CakePHP
Marché B · vérifier le SQL
Vide — 0 occupant
Aucun outil PHP ne relie une requête à son verdict de sûreté, sa ligne de code et sa donnée sensible.

Analyse d'échecs

Nécropsie des query builders PHP. Cause du décès, puis leçon exploitable.
mode profond
Sujet
Cause du décès / de la survie
Leçon
Medoo survivant
A survécu par la simplicité extrême, pas par les fonctionnalités.
Une seule promesse tenue bat dix promesses.
Aura.SqlQuery décédé
Mort d'être correct mais sans distribution.
La justesse technique ne diffuse pas seule.
Micro-ORM PHP famille entière
Meurent quand le framework intègre la même chose gratuitement.
Ne jamais concurrencer une fonctionnalité de framework.
Zend_Db décédé
Mort avec son framework.
Ne pas dépendre d'un écosystème unique.
Propel vaincu
A perdu contre Doctrine par lenteur de communauté.
La vitesse de réponse aux issues est un avantage produit.

Leçon transversale

Les outils PHP qui explosent ne sont pas des bibliothèques mais des outils : Composer, PHPStan, Rector, PHP-CS-Fixer.

Rector est le modèle

Il transforme du code legacy que personne ne veut toucher à la main — et il est massivement installé.

PHPStan est le modèle

Il prouve une propriété du code et s'insère en CI : on l'adopte sans changer une ligne d'application.

Insight Les trois outils PHP les plus installés de la décennie ne s'écrivent pas dans le code applicatif.
